# Contributing

## Purpose

Enable disciplined changes while preserving doctrinal meaning.

## Scope

Code, content, documentation, infrastructure, and conceptual hat transitions.

## Non-goals

This guide does not make judgment transferable.

## Workflow

1. State the visible failure.
2. Inspect the actual artifact.
3. Record intent and the change surface.
4. Classify the change and implement the smallest complete remedy.
5. Run `pnpm affected` and `pnpm build` through both interpretive authorities.
6. Attach evidence and stop.

## Operational impact

Most contributions should have none; this must still be recorded.

## Failure modes

The most common failure is improving the system around an incorrect interpretation.

## Rationale

Direct changes remain direct only after indirect implementation has been considered unnecessary.
